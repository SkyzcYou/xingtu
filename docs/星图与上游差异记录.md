# 星图与上游差异记录

> 本文用于记录星图当前相对上游代码保留的产品差异，以及这些差异背后的实现原因。
> 合并上游代码时，应优先确认这些差异是否仍然符合星图当前产品策略，避免被上游改动误覆盖。

## 总体原则

星图不是完全跟随上游默认产品形态，而是在以下方向上保留自己的产品判断：

1. **品牌与供应商体验以星图为准**：面向用户的品牌、供应商名称、默认渠道不直接沿用上游。
2. **默认功能保持克制**：不向用户展示当前不需要的功能，避免增加理解成本。
3. **外部请求必须明确可控**：涉及价格、供应商接口、API Key 的请求，不能因为上游默认逻辑而自动触发。
4. **优先推荐稳定通用模型**：默认模型与推荐排序以星图当前实际产品策略为准，而不是完全沿用上游排序。

---

## 1. 品牌与默认供应商配置

### 差异

星图保留自己的品牌名称、Logo、默认供应商名称和默认 API Base URL，不完全沿用上游的 Opentu / Tuzi 默认配置。
当前星图侧默认供应商命名更偏产品化，例如：

- `星图ai-通用渠道`
- `星图ai-VIP高速渠道`
- `星图ai-Gemini渠道`
- `星图ai-Codex渠道`

默认 Base URL 也以星图自己的服务入口为准。

### 实现原因

星图是面向用户独立交付的产品，不能在用户可见区域暴露上游品牌或不符合星图产品定位的供应商名称。
供应商配置不仅是技术配置，也会直接影响用户对产品能力、渠道和计费关系的理解，因此需要保持星图自己的命名体系和默认入口。

### 合并上游时注意

上游如果更新了默认供应商名称、Logo、Base URL，需要谨慎合并，不能直接覆盖星图现有配置。

---

## 2. 移除 Business 供应商集成

### 差异

上游新增过 `Business` / `tuzi-business` 默认供应商集成，但星图当前移除了该内置供应商。

星图当前不保留：

- `tuzi-business` 默认 Provider Profile
- Business 默认 Base URL
- Business 默认名称
- Business 自动加入供应商列表
- Business 相关测试预期

### 实现原因

星图当前不需要向用户暴露 Business 渠道。

如果保留该供应商，会导致用户在供应商配置中看到一个当前产品并不准备支持或推荐的渠道，增加选择成本，也可能造成对渠道能力、计费、权限的误解。

### 合并上游时注意

如果上游后续继续添加或恢复 Business 供应商相关代码，星图侧应继续保持移除，除非产品明确决定启用 Business 渠道。

---

## 3. 默认图片模型使用 `gpt-image-2`

### 差异

上游默认图片模型倾向于使用：

```ts
gpt-image-2-vip
```

星图当前默认图片模型保留为：

```ts
gpt-image-2
```

### 实现原因

星图当前更推荐通用的 gpt-image-2，而不是默认引导用户使用 gpt-image-2-vip。

默认模型会影响用户首次使用体验和无显式选择时的生成行为，因此需要选择星图当前更希望主推的模型。

### 合并上游时注意

上游如果再次把默认图片模型改成 gpt-image-2-vip，星图侧应确认后再决定是否接受，不能默认覆盖。

---

## 4. 内置模型推荐分调整

### 差异

上游对以下模型的推荐分是：

```ts
'gpt-image-2-vip': 96
'gpt-image-2': 95
```

星图当前调整为：

```ts
'gpt-image-2': 96
'gpt-image-2-vip': 95
```

### 实现原因

模型推荐分会影响模型排序和用户感知。

星图当前产品策略是更推荐 gpt-image-2，因此需要让它在推荐排序上高于 gpt-image-2-vip。

### 合并上游时注意

上游如果更新模型推荐分，应检查是否重新把 gpt-image-2-vip 排到 gpt-image-2 前面。若星图产品策略未变化，应继续保持 gpt-image-2 优先。

---

## 5. 模型价格展示功能默认关闭

### 差异

上游新增了模型价格获取与展示能力，包括：

- 底部 AI 输入框模型下拉中展示价格
- 聊天抽屉模型选择器中展示价格
- 设置页模型列表中展示价格
- 供应商配置页中展示价格 URL、汇率、分组和"获取价格"按钮
- 启动后自动预热价格缓存

星图当前通过统一开关关闭该功能：

```ts
MODEL_PRICING_FEATURE_ENABLED = false
```

默认关闭时：

- 不显示模型价格标签
- 不显示供应商配置页中的价格配置区域
- 不显示 pricingUrl 输入框
- 不显示 ¥/1USD
- 不显示价格分组选择
- 不显示"获取价格"按钮
- 不执行价格预热
- 即使用户配置了 pricingUrl，也不会启用价格获取

### 实现原因

星图当前暂时不需要向用户展示模型价格。

模型价格展示属于强用户感知功能，可能让用户误以为价格是最终计费标准，或者引发对不同渠道、不同模型价格的额外疑问。在当前阶段，展示该能力会增加产品复杂度，而不是提升核心体验。

因此星图选择保留上游实现能力，但默认彻底关闭用户入口和后台获取行为。

### 合并上游时注意

上游如果继续扩展价格展示功能，星图侧应确保仍然受统一开关控制。

不能只隐藏价格标签，但仍然保留后台自动请求价格接口。

---

## 6. 价格接口不再根据 baseUrl 自动推导

### 差异

上游价格功能曾支持根据供应商 baseUrl 自动推导价格接口，例如：

```ts
https://example.com/v1
```

自动推导为：

```ts
https://example.com/api/pricing
```

星图当前不允许这种自动推导。

即使未来重新启用价格功能，也必须由用户显式填写：

```ts
pricingUrl
```

否则不允许获取价格。

### 实现原因

价格接口请求可能携带供应商 API Key，自动根据 baseUrl 推导请求地址存在产品和安全风险：

1. 用户没有明确同意请求该价格接口。
2. 推导出的 /api/pricing 不一定真实存在。
3. 不同供应商的价格接口规范不一定一致。
4. 可能把 API Key 发送到用户没有预期的地址。
5. 自动请求会让一个本应显式配置的功能变成隐式行为。

因此星图要求价格获取必须显式配置 pricingUrl，不能由系统自动猜测。

### 合并上游时注意

如果上游恢复或增强 baseUrl -> pricingUrl 的自动推导逻辑，星图侧应继续移除或绕过该行为。

---

## 7. "再次生成"采用回填输入框方案

### 差异

星图的"再次生成"不是点击后立即重新发起生成任务，而是将历史提示词和历史参考图回填到底部 AI 输入框，由用户确认后手动发送。

入口包括：

- 画布图片选中后的工具栏
- 任务队列中的生成结果操作

### 实现原因

直接重新生成虽然更自动，但风险更高：

1. 用户可能只是想基于历史参数微调，而不是立即消耗一次生成。
2. 历史任务可能包含多张参考图，需要让用户确认上下文是否正确。
3. 当前输入框可能已有草稿，直接覆盖会造成用户输入丢失。
4. 让用户手动发送，可以复用现有正常生图流程，减少特殊分支逻辑。
5. 回填方案更容易保证与现有模型选择、参考图、提示词、尺寸参数等逻辑一致。

因此星图选择"回填 + 用户确认发送"的交互，而不是"点击即重新生成"。

### 合并上游时注意

如果上游未来提供自己的 Regenerate / Retry 逻辑，需要确认其是否会绕过星图当前的输入框草稿保护、参考图回填和用户确认流程。

---

## 8. gpt-image-1.5 / 旧 gpt-image-1 不作为星图差异保留

### 说明

上游已经移除了旧的内置静态模型：

```ts
gpt-image-1.5
gpt-image-1
```

星图当前跟随上游移除，不再单独保留这些旧模型。

### 实现原因

这些模型已经不再作为上游内置模型维护，星图也没有继续保留它们作为默认内置模型的必要。

### 合并上游时注意

这项不是星图相对上游的差异，而是星图已经跟随上游完成的清理。

---

## 合并上游时的检查清单

每次合并上游后，建议检查以下事项：

- 是否意外恢复了 Business 供应商。
- 是否把默认图片模型改回了 gpt-image-2-vip。
- 是否把 gpt-image-2-vip 推荐分重新排在 gpt-image-2 前面。
- 是否重新启用了模型价格展示。
- 是否重新显示了供应商价格配置区域。
- 是否恢复了根据 baseUrl 自动推导 pricingUrl 的逻辑。
- 是否出现隐藏默认供应商、隐藏默认 API Key 或非用户显式配置的外部请求。
- 是否覆盖了星图品牌名称、Logo、默认供应商名称或默认 Base URL。
- "再次生成"是否仍然走回填输入框方案，而不是点击即自动生成。

---

## 当前结论

星图当前与上游的差异不是临时冲突残留，而是有明确产品原因的定制行为。

这些差异的核心目标是：

1. 保持星图品牌与供应商体验一致。
2. 避免向用户展示当前不需要的价格功能。
3. 避免隐式外部请求和潜在 API Key 风险。
4. 保持默认模型与推荐排序符合星图当前产品策略。
5. 让"再次生成"保持可控、可确认、可复用现有流程。
